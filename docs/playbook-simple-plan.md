# Playbook AI + ContractFlow — simple plan (owner reset, 2026-11-09)

This plan REPLACES the earlier 40-feature roadmap's structure (`docs/playbook-audit-and-plan.md`). The engines already built stay (PBDoc model, PDF/DOCX renderers, versions, editor, brand, variables, numbering, export, catalogue, ContractFlow clone/OTP/tokens); what changes is what the user SEES: one simple structure, three kinds of content, one create flow, and ContractFlow as the only place where anything is sent.

Owner rules: simple; production ready; no dummy/incomplete content; a single agent builds it; speed matters (no TypeScript/lint runs during the build: the owner will check by using it).

## Playbook AI (authoring only: nothing is ever sent from here)
Sidebar: **SOPs**, **Documents**, **Employee KPIs**, **Brand & Letterhead**.

Each of SOPs / Documents / KPIs has the same three screens:
1. **Library** — prebuilt, fully written items (complete content, not blanks). Actions: Preview, Details, Use (copies it into the company's own items; the company can edit anything).
2. **My items** (My SOPs / My Documents / My KPIs) — everything the company created (from the library or from scratch). Actions: Details, PDF Preview, Download (PDF/DOCX), Edit, Delete, **Send to ContractFlow** (the old "send for signature"; creates the clone in ContractFlow, never a message to a signer).
3. **Create from scratch** — 3 steps: (1) Title, Department, Designation (for KPIs: role/employee), Description; (2) AI generation from step 1 (generating → generated → preview); (3) Edit (the editor) and Preview (real PDF). Save.

Brand & Letterhead: step form (1 Identity: logo + name/address lines, 2 Colours and fonts, 3 Header/footer/letterhead, 4 Preview and save).

PDF/DOCX follow the industry standard: cover/title block, document control table (document number, version, date, owner, department, approver), header and footer with page numbers, table of contents, numbered headings, bullet and numbered lists, tables, revision history, approval/signature block, A4.

## ContractFlow (the only place that sends)
Sidebar: **Dashboard**, **SOPs**, **Documents**, **KPIs**.
- Each list shows what Playbook sent, with a status (draft, sent, viewed, signed, rejected/declined, expired, voided) and actions: Edit (edited in place and saved there, never in Playbook), Delete, Details, Preview, Send to client / employee / other.
- Tracking: every state change is recorded with who/when.
- Versioning: every save is a version; Compare any two versions (what changed, when, by whom); full version history.
- **Edit with AI**: a chat panel beside the editor; the user types instructions, the AI changes the document; every AI turn creates a new version with a diff and an Undo.
- **Signer**: link opens an OTP screen (email OTP; SMS only when the company has set it up), then the document opens; signature options: draw, type, upload an image; Submit seals the document; the signed PDF is emailed to the signer (and the company); for employees the signed document also appears in their TalentOS profile.

## Build order (single agent, one phase after another)
P1 Playbook structure and list pages (SOPs/Documents/KPIs share one implementation with a `kind`).
P2 Libraries with complete prebuilt content (seed written in full: SOPs by department, KPI sheets by role; Documents use the 150+ catalogue templates already written; a Console generator can extend the library later).
P3 Create wizard (3 steps) with AI generation for all three kinds.
P4 Brand & Letterhead stepper.
P5 Industry-standard PDF/DOCX layout (cover/control table/TOC/revision history/approval block).
P6 Send to ContractFlow handoff.
P7 ContractFlow dashboard and SOPs/Documents/KPIs lists, edit in place, delete, details, preview, send.
P8 Versioning and comparison UI.
P9 Edit with AI chat panel.
P10 Signer flow (OTP, signature options, sealing, signed PDF email) and TalentOS employee-profile documents.
P11 Optional later: manual e-stamp step, bulk send, renewals.

### Editor pagination like Google Docs print layout (owner feedback round 11)

- **Real pagination that never overlaps:** the plan (`planBreaks`, pure, tested) is computed from measured DOM heights after every edit (throttled 90 ms), resize, zoom, font load and image load. Spacers are view-only widgets, never saved (`scripts/test-pb-editor-decorations-not-saved.ts` serialises a decorated document and compares the saved PBDoc).
- **Long blocks split:** paragraphs and clauses of 4+ lines split between lines with at least 2 lines on each sheet; table rows move whole and the header row repeats on the next sheet; headings and a table's header row stay with what follows; a manual page break starts a new sheet.
- **Header and footer on every sheet** from the brand (same lines, "Page x of y", confidential line); clicking them opens Brand & Letterhead. The Playbook page now builds the header and footer with the same layout input as the export, so the footer text matches.
